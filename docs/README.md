# Документация OMI Landing

## Назначение файлов
- `memory.md` — источник истины: компания, бренд, правила, решения, статус, журнал.
- `brief.md` — выжимка для входа в новый чат без загрузки полной memory.
- `assembly.md` — финальная воронка V10, порядок сборки, чистки старых блоков, прод-задачи.
- `spec/block-NN-*.md` — паспорта СОБРАННЫХ блоков V10: финальные тексты дословно, структура, решения, адаптив. Отвечают на «что сделано и почему именно так».

## Протокол старта нового чата
1. Приложить `docs/memory.md` (или `brief.md` для экономии) + `docs/assembly.md`.
2. Приложить `docs/spec/` того блока, с которым работаем.
3. Сформулировать задачу.
4. Если правим СОБРАННЫЙ блок — дополнительно вставить текущие `indexN.html` / `styleN.css` (код живёт в репозитории, в чатах его нет).
5. Если собираем НОВЫЙ блок — код не вставлять, агент строит по memory/assembly/spec соседей.

## Ведение документации
- После одобрения блока: создать/обновить его spec, обновить memory §8 (статус), §13 (журнал одной строкой).
- История этапов — в git (коммит на блок, теги вех). memory/spec описывают «сейчас», детали прошлого — `git show` или присылкой файла.
- `TODO.txt` в корне упразднён — единственный TODO живёт в memory §12. Файл удалить.
- Формат выдачи в чате задаёт пользователь; по умолчанию — полными файлами.
