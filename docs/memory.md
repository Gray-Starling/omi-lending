## 11. ПРАВИЛА РАБОТЫ С ПОЛЬЗОВАТЕЛЕМ (do / don't)
Общение на русском; ответы по делу, структурированно.
Формат выдачи задаёт пользователь: обычно «выведи полный код», иногда «только скажи что и куда вставить» — следовать формулировке текущего сообщения.
Референсы приходят скриншотами/фрагментами чужого кода как «стилистический референс» (не как замена контента!) — уточнять, что именно заимствуем: смысл или стиль.
Пользователь сам раскладывает файлы по папкам и удаляет лишнее; я указываю имена файлов для сохранения сгенерированных картинок и точные команды миграции.
Don't: переписывать историю версий в код; возвращать тест-классы шрифтов; hover на не-кнопках; visited-перекраску; ведущие нули и круги у номеров этапов; сильные блюры и лишний «воздух»; эксперименты с разделением theme/layout CSS; отдельную промо-секцию; mask/background-color для иконок мессенджеров; полоску версий; добавлять веса шрифтов сверх матрицы.
Like: премиальные тёмные тона; тонкие эффекты (вуали 10px, hairline); уникальность; консистентность бренда; точечные правки по номерам блоков; красный — только точечно в промо-стикерах.
